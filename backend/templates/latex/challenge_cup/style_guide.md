# 挑战杯模版 Style Guide

本指南补充 LaTeX 模版，用于指导系统生成“科学假设与研究计划”，面向挑战杯/大学生科研竞赛语境：问题真实、逻辑清楚、技术路线可执行、数据来源合规、参考文献真实可核查。

## Reviewer Expectations

- 评审首先看“问题是否真实且值得研究”：必须指出当前领域的具体局限性，而不是泛泛描述趋势。
- 研究计划需要有清晰推导链条：从历史数据或已发表研究出发，提出可检验的科学假设，再落到可执行实验。
- 创新点应体现为新的问题切入、变量组合、技术路线、数据采集方式或验证框架，而不是只堆砌模型名称。
- 数据必须来源合规：优先使用公开数据集、政府/机构开放数据、合法授权数据或明确说明拟采集方案。
- 结果部分可以是初步实验、公式推导、可行性仿真或小样本验证，但必须说明验证范围和不确定性。
- 参考论文必须真实存在；不确定的文献不得写入最终 References。
- 全文必须使用中文学术写作。必要英文术语、数据集名、模型名或指标名可保留原文，但应嵌入中文句子中，不得输出英文摘要、英文段落或中英双语章节标题。

## Common Content Structure

挑战杯模版采用“前置研究计划概览 + 标准论文主体”的结构。不要把标题、摘要、参考文献单独展开为正文 section；标题使用 JSON 顶层 `title`，摘要使用 JSON 顶层 `abstract`，参考文献使用 `references` / BibTeX。

### 前置研究计划概览（1 个正文 section，需简洁）

将原 1-6 条挑战杯附加要求合并为 1 个短 section，推荐标题为 **研究计划概览**。该 section 用 6 个简短段落或 `\paragraph{}` 小标题覆盖以下内容，每项 2-4 句即可，不要展开成 6 个独立大 section：

1. **待研究问题：** 指出领域背景、现有方法或现实应用中的明确局限，并给出问题边界。避免与后文“引言”重复。
2. **解决思路：** 串联“已有证据/观察 -> 可检验科学假设 -> 拟采用技术路线”。避免提前展开完整方法细节。
3. **必要的技术手段：** 列明关键技术、工具、模型、统计方法和实验平台，并说明它们服务于哪个验证环节。完整算法放入“方法”。
4. **数据集：** 说明真实数据集/拟采集数据的来源、许可、规模、变量、缺失/偏差和合规性。完整实验配置放入“实验设计”。
5. **Source：** 说明提出假设所依据的历史数据、文献证据、公开统计或已有实验，不写成结果段。
6. **Target：** 说明验证假设需要采集或构造的目标数据、样本、变量、标注、设备、伦理和隐私约束。

### 标准论文主体（正文 sections，按论文逻辑展开）

在“研究计划概览”之后，回到标准论文结构。推荐正文 section 顺序为：

1. **研究计划概览**
2. **引言**
3. **相关工作**（可选但推荐；篇幅受限时可并入引言）
4. **方法**
5. **实验设计**
6. **实验结果与分析**
7. **结论**

章节标题应使用中文，不使用 “Introduction / 引言”“Methods / 方法论” 这类中英双语标题。

## Argument and Tone

- 使用中文学术写作风格：严谨、具体、可验证，避免宣传稿、商业计划书或空泛愿景。
- 每个核心判断都应能追溯到数据、文献、公式、实验或明确假设。
- 将“科学假设”写成可被证伪的命题，例如“在 X 条件下，Y 方法相较 Z 基线可提升 A 指标”。
- 区分“已有证据”“待验证假设”“预期结果”和“潜在应用”，不要混写。
- 不夸大社会价值；价值陈述必须与可验证问题和技术路线相连。

## Evidence Planning

- 至少规划一个强基线和一个简单基线；机器学习任务应包含传统统计/规则方法与主流模型对照。
- 指标必须与研究目标匹配：分类用 Accuracy/F1/AUC，回归用 MAE/RMSE/R2，排序用 NDCG/MAP，因果问题用 ATE/CATE 或稳健性检验。
- 数据集部分必须说明合规性、缺失值、偏差来源、样本代表性和隐私风险。
- Source 与 Target 要形成闭环：历史数据用于提出假设，拟采集数据用于验证假设。
- Results 可以是阶段性，但必须给出公式、表格、数值范围或实验日志，而不是只写“预计可行”。

## Outline Guidance

- 正文 sections 不要超过 7 个主章节。不要把“待研究问题、解决思路、必要的技术手段、数据集、Source、Target”展开为 6 个并列大章节；应合并到“研究计划概览”中简洁呈现。
- 标题、摘要、参考文献不应作为正文 section；主体应使用“引言、相关工作、方法、实验设计、实验结果与分析、结论”等中文标准论文结构。
- “研究计划概览”只说明挑战杯评审需要快速看到的假设链条、数据合规和验证对象；不要提前完整展开后文的方法、实验或结果。
- “必要的技术手段”只说明技术选型与验证环节映射；完整算法和流程放在“方法”。
- “数据集”只说明数据来源与合规性；完整实验配置放在“实验设计”。
- “Source”只说明假设来源；“Target”只说明验证对象；不要把已完成结果写进 Source/Target。
- 如果证据不足，应明确写为“拟验证”或“预期”，不要伪造成已经完成的实验结果。
